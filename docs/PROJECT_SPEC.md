# 서양 점성술 네이털 차트 — 프로젝트 명세

문서 버전: 2.0 · 작성일: 2026-09-21

사용자의 해석 프레임워크와 정밀 차트 생성 요구를 통합한 개발 기준이다. 아래의 기본값·오브·분류 기준은 **서비스의 명시적 규칙**이며, 모든 점성술 학파가 공유하는 단일 정답을 뜻하지 않는다. 전체 제품의 목표 명세이며 모든 기능이 구현됐다는 뜻은 아니다. 현재 로컬 계산 구현 범위와 검증 상태는 [README](../README.md), [기준 비교](REFERENCE_COMPARISON.md), [엔진 검증](engine-report.md)에 기록한다.

## 1. 역할과 정확성의 의미

전문 점성가 수준의 분석 역할로 현대 심리·진화·전통 점성술 관점을 활용한다. 실제 인간 점성가의 경력·자격을 보유한 것처럼 표시하지 않는다.

| 관점 | 참고하는 전문가 | 적용 원칙 |
| --- | --- | --- |
| Modern Psychological | Liz Greene, Steven Forrest, Howard Sasportas | 심리적 경향, 관계 패턴, 성장 가능성 |
| Evolutionary | Jeffrey Wolf Green, Steven Forrest | 성장·변화의 상징적 관점으로 표시; 전생을 확인된 사실로 서술하지 않음 |
| Traditional / Hellenistic | Chris Brennan, Demetra George, Robert Hand | 전통 7행성, 지배성, sect, essential dignity의 체계를 구분 |
| Vedic 참조 | 해당 기법의 확인 가능한 출처 | 별도 비교 관점; sidereal·ayanamsha·하우스 조건을 밝혀 tropical 결과와 혼합하지 않음 |

정확성은 세 부분으로 관리한다: **입력의 신뢰도**, **고정 설정에 대한 수치 계산의 재현성**, **그 수치에 근거한 해석의 일관성**. 천문 수치의 정밀도가 점성술 해석이나 예측의 과학적 타당성을 보장한다는 문구는 사용하지 않는다. 출시 주장은 검증된 입력 범위·설정·허용오차로 한정한다.

## 2. 입력과 불확실성

### 2.1 필수 필드

- 생년월일: Gregorian 양력. 음력 입력은 국가/역법·윤달 여부·변환 도구와 버전을 기록하고 변환된 날짜를 확인받는다. 변환 기능 검증 전에는 양력만 지원한다고 표시한다.
- 출생 시각: 현지 시계의 시·분, 초는 선택. 원문과 `reported | approximate | unknown`, 입력 해상도, 알려진 오차 범위, 기록/기억 등 선택적 출처를 보존한다. 사용자가 입력한 시각이라는 사실과 검증된 출생 기록은 구분한다.
- 출생지: 도시·국가와 필요 시 행정구역. 사용자가 검색 결과를 선택하면 확인으로 간주하고 중복 확인을 요구하지 않는다. 동명 도시를 자동 확정하지 않는다.
- 장소 데이터: 위도·경도, 장소 식별자, 도시 중심/구체 지점 구분, 공급자·버전, IANA zone과 그 판정 출처. 고정밀 경위도 입력도 허용하되 범위를 검증한다.
- 하우스 선호: 기본 Placidus. 검증된 Whole Sign / Equal / Koch / Porphyry를 선택 가능하게 한다. 미구현 선택지는 숨기거나 지원 예정으로 표시한다.

채팅에서는 빠진 필드만 필요한 순서대로 묻는다. 웹 폼에서는 필드를 한 화면에 제시할 수 있으며 기본값은 선호 질문을 대체한다. 이름·성별은 계산 필수값이 아니다.

### 2.2 시간대와 역법

1. 장소의 IANA zone과 **출생 당시** 규칙으로 현지 시각을 변환한다. 현재 UTC offset, 브라우저 시간대, 경도에 비례한 시간 보정을 대신 적용하지 않는다.
2. DST 중복 시각은 두 UTC 후보와 offset을 제시하여 선택받는다. 존재하지 않는 시각은 가능한 offset이 없으므로 시간을 수정하게 하며 자동으로 한 시간을 더하지 않는다.
3. tzdb·timezone 경계 데이터 버전을 고정한다. 과거 국경/행정 변경, 1970년 이전 지역 기록의 불완전성은 별도 출처 검토 대상으로 분류한다. IANA만으로 모든 역사 시각이 보장된다고 주장하지 않는다. 자료의 한계는 [IANA 설명](https://data.iana.org/time-zones/tzdb/theory.html)을 따른다.
4. 역사 시각을 수동 보정할 필요가 있으면 원값·변경값·자료 출처·사유를 저장하는 전문가 모드에서만 처리한다. 자료가 부족하면 `needs_review`로 표시하고 확정 결과를 내보내지 않는다.
5. 초기 검증 목표는 1900–2100년 Gregorian이며 전 세계 지원을 선제적으로 약속하지 않는다. 실제 지원은 엔진·Chiron 데이터·시간대 검증 범위의 교집합으로 선언한다. 미래 출생일은 네이털 입력에서 거부하고 확장 기법의 대상일과 구분한다.
6. Julian calendar와 Julian day는 다른 개념이다. 고대/Julian 입력은 검증된 별도 모드가 있을 때만 지원한다. 분·초가 있는 역사 offset도 정수 시간으로 잘라내지 않는다.

### 2.3 생시 미상·추정 시각

| 모드 | 결과 | 해석 범위 |
| --- | --- | --- |
| Reported | 입력 시각 기준 수치 | 입력 정밀도를 표시하고 정상 해석 |
| Approximate | 대표 시각 결과 + 주어진 구간의 민감도 | 구간에서 바뀌는 사인·하우스·어스펙트·주야 조건을 조건부로 제시 |
| Unknown / Noon | 현지 정오를 대표값으로 사용한다고 명시 + 해당 현지 날짜의 가능 범위 | ASC·MC·DSC·IC·출생 하우스·Fortune·주야 기반 결론을 제외 |
| Solar symbolic | 태양 기준의 상징적 배열 | 실제 출생 하우스·상승궁과 별개로 표시; 선택한 Solar 정의와 버전을 공개 |

추정 시각에 오차 구간이 없으면 임의의 ±분 범위를 만들지 않는다. 사용자가 아는 범위를 추가하거나 Unknown 모드로 전환해야 민감도 기반 해석을 제공할 수 있다.

생시 미상일 때 달뿐 아니라 모든 시간 민감 항목을 검사한다. 현지 날짜의 유효 시간 전체를 평가하며 하루를 항상 24시간으로 가정하지 않는다. 사인 진입, 정지점, 어스펙트 오브 진입·이탈을 찾아 범위를 검증한다. 양 끝값만 비교해 중간 변화가 없다고 결론 내리지 않는다. Noon 시각 자체가 유효하지 않으면 자동 대체 없이 가능한 대표 시각을 명시한다.

구현(2026-09-25, `unknown-day-scan-v1`): Unknown 모드만 활성화했다(Approximate·Solar symbolic은 미구현이라 거절). 대표 시각은 현지 12:00이며, 정오가 존재하지 않거나 두 번이면 선택한 대표 시각과 사유를 경고로 명시한다. 범위는 현지 날짜의 첫 순간부터 다음 날짜의 첫 순간까지(UTC 기준 실제 길이)이고 하루 전체가 지난 날짜만 허용한다. 10분 표본과 경계 이분 탐색, 표본 사이 극값 보정으로 사인 진입·정지·오브 진입/이탈을 찾는다. 검증은 스캔 결과가 아닌 reported 경로(해당 현지 시각의 독립 계산)와 대조한다. 범위 전체에서 유지되는 사인·어스펙트만 안정된 결과로 해석한다. 범위 계산이 미구현이면 대표값이라는 표시만으로 확정 해석을 허용하지 않는다. Solar Chart는 태양의 사인을 1하우스로 삼는 방식과 태양 도수에서 Equal을 시작하는 방식 등을 혼용하지 않으며, 선택한 정의의 검증 완료 후 제공한다.

## 3. 계산 프로필과 엔진

기본 프로필 ID는 `western-tropical-v1`이다. 설정 변경은 결과와 함께 저장한다.

| 항목 | 프로젝트 기본값 |
| --- | --- |
| 황도 | Tropical; 30°씩 나눈 12사인. 실제 별자리(constellation) 경계와 구분 |
| 좌표 | Geocentric apparent ecliptic, true equinox/ecliptic of date, 도 단위 |
| 행성 엔진 요청 | Swiss Ephemeris; `SEFLG_SWIEPH`와 `SEFLG_SPEED`를 함께 지정 |
| 하우스 | Placidus; 각도점은 하우스 시스템과 별도 데이터 |
| Node | True North Node; Mean은 별도 옵션 |
| Lilith | Mean Black Moon, lunar apogee; 종류를 항상 표시 |
| 하우스 소속 | §5의 황경-커스프 구간 규칙 |
| 주요 오브 | §6의 버전 관리되는 서비스 규칙 |
| 해석 | 심리 관점 기본, 전통 분석은 해당 체계를 표시 |

Swiss Ephemeris 원본 또는 검증된 binding/WASM adapter를 사용한다. `swisseph-wasm`은 후보이지 검증·채택 완료를 뜻하지 않는다. Web search는 공식 문서 확인과 참조값 비교에 쓰며 검색 요약·LLM 응답을 출생 수치의 생성 엔진으로 사용하지 않는다.

필수 엔진 계약:

- 시간 파이프라인: 현지 civil time → 확정 UTC → 엔진의 시간 변환 → 별도의 `jdUt1`, `jdTt`. UT 계열 호출에는 UT1을, TT 계열 호출에는 TT를 전달하고 ΔT를 중복 적용하지 않는다. 윤초 자료와 1972년 이전 시간 처리 정책을 기록한다. [S1 §9–10]
- engine/binding 버전, 천체력 파일명·해시·지원 범위, ΔT 정책, 요청/반환 flags를 manifest와 결과 메타데이터로 추적한다. 실제 사용 데이터가 고정되었는지 확인한다. [S1, S2]
- 반환 오류·경고와 실제 계산 방식을 검사한다. 승인되지 않은 Moshier fallback, 데이터 누락·손상, NaN/Infinity는 계산 실패다. 대체값이나 0°를 성공 결과로 표시하지 않는다. [S1 §3.5]
- Chiron 등 별도 데이터가 필요한 대상도 같은 검증을 거친다. 실패 시 해당 값·그에 의존하는 해석을 비우고 §12의 `blocked / partial` 상태 규칙을 따른다.
- 전역 엔진 설정이 요청 간 섞이지 않도록 context/worker 격리 또는 직렬화를 적용한다. 다른 출생지·프로필 동시 요청으로 검증한다.

이 프로필은 의도적으로 sidereal, topocentric, heliocentric, J2000, 임의 nutation 비활성화를 선택하지 않는다. 필요 시 별도 프로필과 참조 검증을 추가한다.

## 4. 산출 대상과 표시

Reported 모드의 완성 네이털 결과에는 아래 항목을 모두 포함한다. 다른 입력 모드에서는 §2.3에 정한 제외·조건부 표시를 적용한다. 수치 모델에는 계산 전 원문 입력과 정규화 입력을 구분해 연결한다.

| 대상 | 필수 결과·정의 |
| --- | --- |
| Sun, Moon, Mercury, Venus, Mars, Jupiter, Saturn, Uranus, Neptune, Pluto | 황경·황위·속도·사인·사인 내 도수·하우스·이동 방향 |
| ASC, MC | 엔진 계산값 |
| DSC, IC | 각각 ASC·MC의 대척 황경 |
| North / South Node | 선택한 종류의 North와 대척 South; 서로 다른 node 종류를 섞지 않음 |
| Chiron | 별도 소천체로 구분하고 데이터 가용성을 검증 |
| Lilith | Mean lunar apogee 기본; Osculating(`lilith_mode: osculating`, "오스큘레이팅 릴리스")을 별도 이름으로 지원(2026-09-25). Interpolated는 미지원. 소행성 1181 Lilith와 구분 |
| Part of Fortune | §5의 주야 공식과 사용한 sect |
| 12 cusps | 번호 1–12와 사인·도수·원시 황경 |
| Aspects / Dignities | §6–7의 규칙과 판정 근거 |

황경은 `norm(x) = ((x % 360) + 360) % 360`으로 [0°, 360°)에 둔다. 사인 번호는 `floor(longitude / 30)`, 사인 내 도수는 나머지다. 부호·단위 변환을 adapter 한 곳에서 관리한다. 지리 위도·경도는 북·동 양수, 남·서 음수인 십진 도를 사용한다.

원시값은 엔진의 부동소수 정밀도를 유지한다. 기본 DMS 표시는 사인 경계를 넘기지 않도록 초 미만을 버리고 표시 규칙을 명시한다. 사인·하우스·어스펙트 판정에는 표시값을 재사용하지 않는다. 소수점 자릿수를 입력 정확도로 설명하지 않는다.

황경 속도가 음수면 R, 양수면 D다. 정확히 0인 경우 방향 미정으로 표시한다. 정지점(station) 강조는 천체별 허용 기준과 검증된 정지시각 탐색이 있는 경우에만 추가한다. True Node를 항상 역행으로 강제하지 않는다. ASC·MC·Fortune의 R은 기본 `not_applicable`이다.

## 5. 하우스, 주야, Part of Fortune

- Placidus, Koch, Porphyry, Whole Sign, Equal의 엔진 코드와 결과 배열 인덱스를 adapter에서 확인한다. Equal은 ASC 도수에서 시작하는 방식으로 정의한다.
- 추가(2026-09-25): Regiomontanus(R, 천구 적도 등분), Campanus(C, 주수직권 등분), Alcabitius(B, ASC 반호 3등분 후 적경 투영). 세 시스템의 11·12·2·3 커스프는 RAMC·진황도경사·위도로 쓴 닫힌 식과 1″ 이내로 대조한다. 고위도에서 커스프 순서가 역전되면 (예: 80°N의 R/C) 기존 순서 검사로 `HOUSE_SYSTEM_UNAVAILABLE`을 반환한다. ASC는 지평선 위의 점이므로 Alcabitius의 반호는 항상 정의된다.
- Whole Sign의 1하우스 시작은 ASC 사인의 0°이고 ASC 도수는 별도로 보존한다. Equal의 1하우스 커스프는 ASC 도수와 같다. 두 시스템 모두 MC는 독립 각도점이므로 10하우스 커스프로 덮어쓰지 않는다.
- 하우스 실패를 반환 코드로 검사한다. 극지 Placidus/Koch의 자동 Porphyry 결과는 요청 시스템의 성공 결과가 아니다. 사용자가 지원되는 대안을 선택하면 새 설정으로 계산한다. 모든 위도에서 모든 시스템이 가능하다고 가정하지 않는다. [S1 §15–16]
- 기본 행성 하우스는 황경을 cusp i부터 다음 cusp 직전까지의 순환 구간 `[cusp_i, cusp_next)`에 배정한다. cusp와 정확히 같으면 해당 하우스다. 12→1의 0° 경계를 처리하고 각 천체가 정확히 한 구간에 속하는지 검사한다.
- 행성 황위를 반영하는 mundane house position은 별도 기법이다. 기본 황경 구간 방식과 혼합하지 않는다. 다음 하우스에 가까우면 옮기는 이른바 5° 규칙도 기본값에 적용하지 않는다.
- sect는 출생지에서 태양 중심의 **기하학적 고도**로 판정한다. 서비스 기본은 geocentric 태양 좌표를 해당 지평 좌표로 변환하고 굴절·지형 보정을 제외하며, 고도 ≥ 0°면 day, < 0°면 night다. 이 경계 정의를 공개하고 경계 근처 출생 오차는 민감도로 표시한다.
- Fortune 공식은 day: `norm(ASC + Moon − Sun)`, night: `norm(ASC + Sun − Moon)`이다. 모두 같은 프로필의 황경을 사용한다. 종일 주간식을 사용하는 다른 관습과 비교할 때는 설정 차이를 표시한다. 주야 반전은 [전통 정의](https://www.skyscript.co.uk/glossary/part-of-fortune/)를 채택한다.
- 생시 미상 또는 오차 구간이 주야 경계를 넘는 경우 Fortune·sect를 확정값으로 해석하지 않는다.

## 6. 어스펙트와 패턴

### 6.1 주요·부가 어스펙트

두 황경의 최단 거리 `d = min(norm(a − b), 360 − norm(a − b))`를 구하고, 목표각 θ에 대해 `orb = abs(d − θ)`로 판정한다. 오브가 허용값과 같으면 포함한다. ±각의 방향성은 applying 판정을 위해 별도로 보존한다.

| 어스펙트 | 목표각 | 10행성 사이 기본 오브 |
| --- | --- | --- |
| Conjunction / Opposition | 0° / 180° | 8° |
| Square / Trine | 90° / 120° | 6° |
| Sextile | 60° | 4° |
| Quincunx | 150° | 3°, 요청 시 목록 표시; Yod 판정에는 내부적으로 사용 |
| Semi-square / Sesquiquadrate / Quintile | 45° / 135° / 72° | 2°, 요청 시 |

구현(2026-09-25, 규칙 `aspects-v3`): 부가 어스펙트는 `aspect_profile.minor`로 선택하며 Luminary 가산이 없다. `orb_scale`(0.5–1.4, 기본 1)은 10행성 쌍의 기본 오브(가산 포함)와 추가점의 기본 오브에 곱하고, 추가점의 사용자 상한(≤3°)과 부가 상한(2°)은 그대로 적용한다. 1.5배 이상에서는 Sextile/Quintile, Trine/Sesquiquadrate의 허용 범위가 겹쳐 한 쌍이 두 어스펙트를 동시에 만족할 수 있으므로 상한을 1.4로 둔다(테스트로 모든 범위의 비중첩을 검사). 표에 없는 Biquintile(144°)은 제공하지 않는다. 이전 `major-v2` 프로필은 부가 없음·배율 1의 `aspects-v3`로 정규화되어 같은 결과를 내며, `major-v2`에 minor·orb_scale을 함께 보내면 거절한다. 컴포지트는 두 차트의 하우스·노드·Lilith·어스펙트 설정이 다르면 미드포인트를 만들지 않는다.

원안에서 비어 있던 목성 이후 행성 규칙을 위와 같이 10행성 공통값으로 명시한다. Sun 또는 Moon이 한쪽 이상인 **주요** 어스펙트는 +2°를 한 번만 더한다. Sun–Moon에도 +4°로 누적하지 않는다.

Chiron·Node·Lilith·Fortune·각도점이 하나라도 포함된 경우 주요 오브 상한은 3°, 부가 상한은 2°이며 Luminary 가산을 적용하지 않는다. 기본 표는 10행성 상호 간 및 10행성↔추가 대상의 주요 어스펙트다. 추가 대상끼리와 부가 어스펙트는 명시적 확장 옵션이다. 축의 대척점에서 파생되는 중복 관계는 연결해 표시하고 패턴 점수에 중복 반영하지 않는다.

천체쌍은 순서와 무관한 고유 ID를 가진다. 각 어스펙트는 원시 분리각, 목표각, 실제 오브, 허용오브, 규칙 버전을 보관한다. 사용자가 orb를 바꾸면 결과·패턴을 재계산한다.

Applying/separating은 현재 각거리의 해당 목표각에 대한 오차가 줄거나 늘어나는지 상대 황경 속도로 판정한다. 0°/180° 접힘, 정지점, 정확한 접촉의 허용오차는 별도 검사한다. 이 상태는 **국소적인 접근/이탈**이며 미래 exact event 발생을 보장하지 않는다. 첫 출시에서는 검증된 10행성 쌍에만 제공하고 그 외는 `not_evaluated`로 둔다.

### 6.2 주요 구성의 자동 인식

기본 참여 대상은 10행성이다. 포인트 추가는 별도 설정으로 하며 아래 구성은 필요한 모든 연결을 만족할 때만 검출한다. 패턴 오브는 §6.1의 각 쌍 오브를 사용한다.

| 구성 | 검출 조건 |
| --- | --- |
| Stellium | 3개 이상이고 모든 쌍이 합 조건을 만족하는 그룹. 연결만 이어진 합 연쇄와 구분 |
| T-Square | 대립 1쌍과 양 끝 각각에 square인 제3행성 |
| Grand Cross | 서로 다른 4행성, 대립 2개와 순환 square 4개 |
| Grand Trine | 서로 다른 3행성의 모든 쌍이 trine |
| Kite | Grand Trine + 그중 하나와 대립하고 나머지 둘과 sextile인 제4행성 |
| Yod | sextile 기저 1쌍 + 양쪽에 quincunx인 꼭짓점. 검증된 quincunx 규칙을 내부적으로 사용하며, 부가 목록 표시 여부와 독립적으로 검출 |
| Mystic Rectangle | 서로 다른 4행성, 대립 2개·trine 2개·sextile 2개가 직사각형 순환 연결 |

같은 사인/하우스에 3개가 있다는 사실은 별도 집중도로 표시하고 합 기반 Stellium과 구분한다. 사인 경계를 넘는 degree aspect는 허용하되 그 사실을 표시한다. 전통의 whole-sign aspect를 추가할 때는 별도 모드로 제공한다. 하위 패턴과 같은 참여 집합의 중복을 연결하되 삭제해 근거가 사라지게 하지 않는다.

## 7. 디그니티와 지배성

전통 essential dignity는 Sun부터 Saturn까지 7행성에 적용한다. 결과를 단일 등급 하나로 축약하지 않고 조건별 배열로 저장한다. 사인 수준의 detriment/fall과 작은 dignity가 공존하는 경우도 보존한다.

- Domicile, exaltation, detriment, fall은 출처와 검증 사례를 갖춘 표로 관리한다. Exaltation의 사인과 특정 exaltation degree는 다른 필드다.
- Triplicity / bound(term) / face(decan)는 체계가 다를 수 있으므로 출처, 주야 지배자 정책, 경계의 포함 방향을 명시해 버전 관리한다.
- **Peregrine**은 선택한 전통 체계에서 essential dignity가 없는 경우에만 판정한다. 네 가지 사인 상태가 없다는 이유만으로 peregrine이라 하지 않는다. Triplicity·bound·face 미평가 상태에서는 `not_evaluated`이며, 이 평가 완료가 완전한 전통 dignity 기능의 활성화 조건이다. [정의 근거](https://www.skyscript.co.uk/glossary/peregrine/)
- Uranus/Neptune/Pluto의 현대 rulership은 각각 Aquarius/Pisces/Scorpio에 대한 별도 현대 관점으로 표시한다. 외행성·Chiron·Node·Lilith에 합의되지 않은 고양/실추 표를 만들어 적용하지 않는다.
- Chart Ruler는 전통 지배성을 기준으로 표시하고 Scorpio/Aquarius/Pisces는 현대 지배자를 별도로 병기한다. 해당 구분을 밝혀 Mars/Pluto, Saturn/Uranus, Jupiter/Neptune을 섞은 단일 판정을 만들지 않는다.
- Angularity 등 accidental dignity와 essential dignity를 구분한다. 별도 점수 모델을 검증하지 않았다면 임의 합산 점수를 제공하지 않는다.

## 8. 통합 해석 프레임워크

각 문장은 `배치/어스펙트 등 근거 → 가능한 심리·생활 패턴 → 선택·활용 방향`을 연결한다. LLM에는 검증된 ChartResult와 규칙/출처 ID를 제공한다. 수치·하우스·패턴의 추가 생성은 결과 검증기로 차단한다. 충돌하는 경향은 함께 설명하며 한 요소로 성격·관계·사건을 확정하지 않는다.

### 1단계: 차트 개요

- Big Three: Sun / Moon / ASC. 불확실한 값은 §2.3의 범위로 제한한다.
- Chart Ruler와 배치·어스펙트.
- 원소 Fire/Earth/Air/Water와 모드 Cardinal/Fixed/Mutable: 기본은 10행성 각 1점의 분포다. ASC/MC/Node를 조용히 추가하거나 개인행성 가중치를 몰래 적용하지 않는다. 가중 분석은 분모·가중치가 공개된 별도 표로 제공한다.
- East/West, North/South 강조: 기준과 집계 대상을 먼저 고정한다. 실제 지평 반구는 고도·방위/시간각 기준으로, 하우스 기반 분포는 선택 시스템의 하우스 기준으로 계산해 서로 구분한다.
- Chart Shape: Bowl / Bucket / Bundle / Locomotive / Seesaw / Splash / Splay / Fan을 분석 범위로 둔다. 활성화 전 참여 대상, 점유호·빈 구간, handle/군집 기준, 경계값·우선순위, 양성/반례를 버전 관리한다. 분류가 겹치거나 정의가 부족하면 `mixed / unclassified / not_evaluated`로 반환한다.

### 2단계: 주요 패턴

§6.2의 구성과 각 구성의 실제 참여 천체·어스펙트·오브를 제시한다. 검출되지 않은 구성 이름을 설명 편의를 위해 추가하지 않는다.

- Angular 강조는 선택 하우스의 1/4/7/10H 소속과 실제 ASC/MC/DSC/IC 근접도를 구분한다. 근접 판정 기준은 활성화 전 고정한다.
- Elevated Planet은 기하학적 고도 순위와 MC 황경 근접을 구분하고 어떤 지표인지 표시한다.
- Singleton은 원소/모드 등 분류 축과 참여 집합을 고정하고 해당 범주의 유일한 행성인지 검사한다.
- Out-of-bounds는 요청 시 적위와 선택한 황도 경사 기준으로 검증한다. 황위·황경으로 대체하거나 모든 시대에 고정된 상수를 적용하지 않는다.

### 3단계: 행성별 심층 분석

사인 × 하우스 × 주요 어스펙트를 삶의 서사로 통합한다. 전통 dignity/sect 또는 진화 관점을 사용할 때는 관점을 명시한다. 외행성 사인만으로 개인의 특징을 강하게 단정하지 않고 세대적 맥락과 개인 차트의 연결을 함께 본다.

### 4단계: 삶의 영역

관심 영역을 우선하고 12하우스 모두를 지원한다: 1H 자기표현, 2H 가치·재물, 3H 소통·학습, 4H 뿌리·가정, 5H 창조·자녀, 6H 일상·건강, 7H 파트너십, 8H 공유자원·변형, 9H 신념·탐구, 10H 커리어·평판, 11H 공동체·비전, 12H 내면·고립·보이지 않는 활동. 입주 행성이 없다는 이유로 해당 영역이 없다고 해석하지 않는다.

### 5단계: 종합

핵심 테마 3–5개, 강점과 도전, 성장 방향, shadow 패턴을 정리한다. 각 테마의 근거와 상반된 요소를 밝혀 재현 가능한 해석으로 만든다.

## 9. 기본 출력과 차트 시각화

1. **차트 요약 표**: 행성·포인트의 사인/도수/하우스/R, 각도점·Nodes, 적용 가능한 dignity, 주요 aspects. 계산 불가와 미평가를 빈칸/0°로 혼동하지 않는다.
2. **첫인상**: Big Three와 원소 분포를 중심으로 3–4문장. 생시 미상에는 ASC를 제외한다.
3. **심층 해석**: 관심 영역 우선, 없으면 성격 → 관계 → 커리어 → 성장 과제.
4. **실용적 통찰**: 활용할 강점, 주의할 패턴, 선택 가능한 행동. ‘현재 시기’라는 주장은 실제 transit 등 대상일 계산이 있을 때만 제시한다.
5. **계산 정보 펼치기**: 입력 모드, 현지 시각/UTC/offset, 장소·좌표, zodiac/houses/node/Lilith, 계산·데이터·규칙 버전, 제한사항. 엔진 세부 플래그는 기술 상세나 export로 제공한다.

SVG 원형 차트와 aspect grid는 동일 ChartResult를 사용한다. 차트 방향·회전 기준을 고정하고 0° 래핑과 ASC/MC 위치를 검증한다. glyph 겹침을 줄이기 위해 라벨을 옮겨도 실제 도수 tick/연결선은 보존한다. 하우스의 시각적 폭을 실제 cusp 간격에 맞추고 결과 표와 대응시킨다. 색상 외 기호/선 종류로 구별하며 SVG에 접근 가능한 설명과 텍스트 표를 제공한다.

## 10. 언어·윤리·사용자 맥락

- 한국어 기본, 전문 용어 영어 병기. 중급~고급 사용자를 위해 단순 키워드보다 복합 배치·기법 차이를 설명한다.
- ‘이 배치는 … 경향을 시사한다’, ‘이런 방식으로 경험될 수 있다’처럼 경향·패턴·선택의 언어를 사용한다. 강점과 shadow를 균형 있게 연결한다.
- 어스펙트와 배치를 결정된 미래로 표현하지 않는다. 사망·질병·사고를 예언하지 않으며 의료·법률·재정 결정을 대신하지 않는다.
- 궁합은 상호작용을 설명하고 일방적 맞음/틀림이나 결혼/이별 명령을 내리지 않는다.
- 사용자에게 도움이 되면 십성↔행성 원형, 격국↔패턴, 대운↔progression/transit을 **이해를 위한 비유**로 비교한다. 일대일 등가·공통 계산법으로 주장하지 않는다.
- 전문가 이름을 허구의 인용·추천 근거로 사용하지 않는다. 특정 저자의 기법이나 문장을 언급할 때는 확인 가능한 출처를 연결한다.

계산 상태 `success / partial / blocked`와 입력 신뢰도는 별도 필드다. 미평가·적용불가·불확실·실패도 구별한다. 오류 코드에는 `INVALID_INPUT`, `AMBIGUOUS_LOCAL_TIME`, `NONEXISTENT_LOCAL_TIME`, `TIMEZONE_NEEDS_REVIEW`, `UNSUPPORTED_DATE`, `EPHEMERIS_DATA_MISSING`, `UNEXPECTED_EPHEMERIS_FALLBACK`, `HOUSE_SYSTEM_UNAVAILABLE`을 포함하고 사용자 메시지와 대응시킨다.

시간 변환 미해결, 10행성 계산 실패, 요청 모드의 하우스 계산 실패는 `blocked`다. Chiron 등 추가 대상만 실패하고 기본 수치가 유효하면 `partial`로 남은 수치를 보여줄 수 있으나 완성 결과로 저장·공유하지 않는다. Unknown 모드에서 정의상 제외한 하우스처럼 의도된 제외는 실패가 아니며, 해당 모드의 필수 검증을 통과하면 모드를 표시한 `success`가 가능하다.

결과는 위 입력·버전·파일이 같으면 동일하게 재생성되어야 한다. 캐시 키에 날짜/시간·좌표·모든 결과 영향 설정과 버전을 포함한다. 엔진 결과 스키마를 검증한 후 렌더링·해석한다. 알 수 없는 항목을 0, Aries, 1H 같은 정상값으로 대체하지 않는다.

출생 데이터 저장 정책(2026-09-23 개정, 동의 기반): 차트 계산 요청(성공·`ChartError` 실패 모두)마다 관리자 전용 저장소(SQLite `data/admin.sqlite3` 또는 Postgres, `natal/store.py`)에 한 행을 기록하되, **원문 계열 열**(`raw_input`·`display_name`·`place`·`summary`·`fingerprint`)은 사용자가 기본 해제된 저장 동의 체크박스를 선택한 경우(`client.store_consent === true`, 이전 클라이언트가 항상 보내던 `consent` 필드는 동의로 보지 않음)에만 저장한다. `consent` 열은 0=비동의, 1=이전 고지 기반 정책으로 저장된 기존 행(이전 앱이 항상 쓰던 값이라 배포 전환 중에도 의미가 바뀌지 않음), 2=동의이며, 기존 행도 같은 180일 만료를 따른다. 동의가 없으면 이름은 클라이언트에서 전송하지도 않으며, 행에는 상태·오류 코드·태양/달/ASC 사인·익명 방문자 ID·UTM만 남는다. 원문 계열 열은 생성 후 180일(`RAW_RETENTION_DAYS`)이 지나면 NULL로 지우고 통계 열은 유지한다. 서버리스에 스케줄러가 없으므로 기록·관리자 조회 때마다 만료 정리를 실행한다. 사용자는 `POST /api/my-data/delete`(브라우저의 무작위 방문자 ID를 삭제 전용 키로 사용, 같은 Origin만)로 자기 브라우저의 모든 행을 직접 삭제할 수 있고, 관리자는 원문이 없는 행을 재계산하지 않는다(`409 RAW_INPUT_NOT_STORED`). 폼에 저장 범위·보관 기간·직접 삭제 버튼을 고지한다. 사용자 식별은 사용자가 입력한 이름/닉네임과 브라우저가 생성한 무작위 익명 ID(localStorage, fingerprinting 없음)로만 하며, 첫 유입 UTM(`utm_*`, `sc`)을 검증 후 함께 기록한다. 이 운영 정보는 요청의 별도 `client` 객체로 전달되어 엔진에 전달되지 않고 결정적 ChartResult에 포함되지 않는다. 저장 실패는 차트 응답을 막지 않는다. 열람·통계·삭제는 비밀번호 인증된 관리자(`/admin`, `/api/admin/*`)만 가능하며, 관리자는 입력 기록·방문자 단위 삭제 경로를 제공한다. 원문은 이 저장소 외의 접근 로그·분석 이벤트·공유 URL에 남기지 않는다.

UTM 단축 링크(2026-09 추가, `natal/utm.py`, 스키마 v2): 관리자가 만든 링크는 사이트 내부 경로만 목적지로 가질 수 있다(외부·프로토콜 상대 URL은 애플리케이션과 DB CHECK 양쪽에서 거절). `/l/{code}` 클릭은 `utm_clicks`에 코드·시각·집계 여부(`counted`)·제외 사유(`head`/`preview-bot`)·UA 계열 이름(`ua_family`)만 저장하며 **IP 주소와 User-Agent 원문은 저장하지 않는다**. 클릭 기록 실패는 리다이렉트를 막지 않는다. 입력 귀속은 `submissions.short_code` 기준이며, 단축코드 없이 utm만 있는 입력은 “UTM 직접 유입”으로 분리 집계한다. 채널·캠페인·링크는 물리 삭제 대신 `is_active`/`archived_at`으로 숨긴다.

지오코딩은 장소 검색어만 전달하고 이름·출생 일시를 동봉하지 않는다. 외부 해석 모델을 사용하면 사용자에게 처리 범위를 알리고 명시적 이용 선택 후 최소화된 차트 데이터만 전송한다. 공유는 별도 사용자 동작과 삭제 경로를 제공한다. 원문 출생 데이터나 해시를 공개 분석 로그에 남기지 않는다.

## 13. 검증과 출시 조건

### 13.1 독립 기준값

앱과 같은 adapter 출력으로 기대값을 만든 뒤 앱을 검증하지 않는다. 동일 엔진/데이터 버전의 독립 `swetest` 실행 등으로 고정 fixture를 만들고 명령·입력·설정·원시 출력·출처를 보존한다. 이는 통합 오류 검사이며 엔진 자체에 대한 독립 천문 인증으로 표현하지 않는다.

사용자 레퍼런스 사이트와의 비교는 UTC, 좌표, tropical/sidereal, house, node, Lilith, Fortune 공식, apparent/geocentric, house 배정 방식이 같을 때 수행한다. 설정을 확인할 수 없으면 참고 수준으로 기록한다. 독립 천문 자료와 비교할 때도 시간척도·기준면·관측점 등 좌표 조건을 일치시킨다. 화면의 분 단위 값만으로 초각 정확도를 인증하지 않는다.

초기 **동일 버전·설정 수치 회귀 목표**는 황경·ASC/MC·cusp의 원형 차이 ≤ 1초각(1/3600°)이다. 이는 관측 정확도나 출생 정보의 오차가 아니다. 다른 출력값은 검증 도입 시 단위별 허용오차를 기록하고 sign/house/aspect/state 같은 분류는 정확히 일치해야 한다. 경계 사례를 허용오차로 통과시키지 않는다. 근거 없는 오차 한도 확대 대신 차이 원인을 조사한다.

## 14. 개발 순서와 범위 결정

1. **계산 검증 기반**: engine adapter·데이터 manifest·시간대 변환·독립 fixture를 확보한다. 완료 조건은 정상 사례와 실패 사례가 자동 판정되는 것.
2. **네이털 생성**: 입력 모드, 필수 천체/포인트, 5개 house 시스템, 주요 aspects, 시각화를 연결한다. 완료 조건은 표·SVG·메타데이터의 일치와 지원 기능별 회귀 통과.
3. **해석 기능**: dignity 세부 체계·분포/형태 분류 규칙을 출처와 함께 고정하고 근거 추적 해석을 연결한다. 완료 조건은 판정 근거 재현과 미평가 항목의 해석 제외.
4. **확장 기능**: §11의 대상·규칙을 기능별로 확정하고 검증 후 활성화한다.

자료 선택이 아직 필요한 항목은 engine binding, 지오코딩/역사 시간대 provider, 음력 변환 provider, 전통 dignity 세부 표, chart shape·angularity·반구 분류 임계값, Solar symbolic 방식, 확장 기법별 프로필이다. 이는 개발 시 출처·테스트와 함께 결정할 항목이지 계산을 임의로 채워 넣어도 된다는 뜻이 아니다. 이후 사용자 레퍼런스에 따라 기본값을 변경하면 규칙 버전과 fixture도 함께 갱신한다.
